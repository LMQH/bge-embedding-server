# PRD-0003：嵌入结果缓存

- 状态：已确认，2026-10-22。
- 来源与确认依据：2026-10-22 用户在服务性能方向讨论后明确指定"增加优化，方向是缓存"，并要求进行决策与制定优化计划；同日用户指示"不跑本机真实验证，执行修改，然后推到 Mac mini 上去测试"，即为对本 PRD 及关联决策、规格的确认，真实服务验证改在 M4 执行。
- 关联：[PRD-0001](0001-embedding-service.md) · [ADR-0006](../adr/0006-in-memory-result-cache.md) · [SPEC-0001](../specs/0001-embedding-inference.md) · [SPEC-0003](../specs/0003-result-cache.md) · [PLAN-0009](../plans/0009-result-cache.md)

## 背景、用户与场景

嵌入推理是纯函数：同一模型快照下，相同 token 输入与相同输出选项必然得到相同结果。当前服务对重复文本（知识库文档重复入库、热点查询反复到达）每次都完整推理；8192 tokens 约 4.8 秒，短文本约 25 毫秒，且单执行位串行，重复请求白白占用唯一的 GPU 执行位置并推高排队延迟。

在进程内保存最近的推理结果，命中时直接返回，可将重复文本延迟从秒级 / 十毫秒级降到微秒级，并减少队列占用。用户与调用方不变：内网知识库 / RAG 调用方；接口、鉴权、错误码与 usage 语义不变。

## 目标与范围

目标：

- 相同文本与相同输出选项的请求直接复用已计算结果，命中延迟显著低于推理延迟。
- 缓存容量有硬性上界，不因稀疏条目大小差异或长期运行而无限增长。
- 对外契约透明：不新增字段、端点或错误码；未命中路径行为与现状一致。

本次包含：

- 按文本条目粒度的进程内内存缓存；请求内逐条查缓，未命中子批照常进入推理任务。
- 以 token 序列哈希为键；命中结果与推理结果逐位一致。
- LRU 淘汰与按估算字节的容量预算；TOML 配置开关与上限。
- 请求日志追加命中条数；相关 Spec、Plan、配置示例与索引更新。

本次不包含：

- 跨进程、分布式或磁盘持久化缓存；重启后缓存为空。
- 检索效果优化、模型 / 量化变更、embedding 算法调整。
- 新端点、新响应字段、新错误码；调用方无感知。
- M4 部署执行（部署需用户单独授权，方案见 [PLAN-0009](../plans/0009-result-cache.md)）。

| 需求 ID | 需求 | 验收标准 |

| REQ-024 | 兼容回归：鉴权、请求校验、错误码、队列与 429 语义不变；现有测试与真实调用回归通过。 | SPEC-0003 AC-302、AC-303、AC-306 及现有 smoke 通过。 |

## 成功标准

- 真实服务上同一文本第二次请求耗时显著低于首次，且输出逐位一致。
- 全命中请求在 GPU 忙碌（有推理任务执行中）时仍立即返回，不占用 20 个位置。
- 长期运行下缓存内存占用不超过配置预算；关闭开关后行为与现状无异。
- 不新增运行时依赖；文档、配置示例与实现一致。

## 约束与待讨论事项

- "不持久化"边界：SPEC-0001 规定服务不持久化用户文本和返回向量，指不落盘、不长期保存；进程内存驻留的缓存随进程消失，不构成持久化。该边界在 [ADR-0006](../adr/0006-in-memory-result-cache.md) 记录。
- 容量预算按估算字节而非条目数：sparse 条目大小随文本长度差异大（短句数百字节，长文可达 MB 级），条目数上限无法给出内存硬界。
- max_bytes 示例基线 256 MiB（与 MLX 缓存回收目标同量级）；实际值由私有 TOML 决定，实施时以 RSS 实测校准。
- 命中不改变 API 契约与队列语义；`queue_full` / `queue_timeout` 仅可能发生在含未命中条目的请求，该澄清写入 SPEC-0003。
- M4 16GB 的实测内存与延迟证据待部署阶段补充；本 PRD 不预支 M4 结果。
