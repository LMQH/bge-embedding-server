# PRD-0004：请求观测、请求内去重与过载提示

- 状态：已确认，2026-10-23。
- 来源与确认依据：用户 2026-10-23 指示先实施 O1（请求日志观测）、O2（请求内重复文本去重）、O4（429 返回 `Retry-After`），并要求先制定 Spec 与 Plan、再执行。现状与局限见 [REF-0003](../references/0003-service-limitations.md)。
- 关联 Spec / Plan：[SPEC-0004](../specs/0004-request-observability-and-dedup.md)、[PLAN-0010](../plans/0010-request-optimizations.md)。

## 背景、用户与场景

当前请求日志只有总耗时、批量、token 数与缓存命中数，无法区分排队等待与推理执行；同一请求内的重复文本会逐条推理；429 没有退避提示。接入方在入库高峰或批量重复文本场景下，既难以判断瓶颈，也只能凭经验重试。

本批优化面向运维与调用方：用最小改动让请求级瓶颈可见、减少同一请求内的重复计算，并给过载响应一个明确的退避信号。服务仍是单机单模型、串行执行，不改变对外 API 形状。

## 目标与范围

包含：

- 请求完成日志追加 `wait_ms`、`exec_ms`、`ahead`、`dedup` 四个安全元数据字段。
- 同一请求内 token 序列完全相同的条目只推理一次，响应仍逐条对应，`usage` 不变。
- `429 queue_full` / `429 queue_timeout` 返回 `Retry-After: 1`。

不包含：

- 跨请求 in-flight 合并、执行超时、长请求隔离、启动预热；GPU 合批已由 [PLAN-0011](../plans/0011-batch-inference.md) 单独实施。
- `/metrics` 端点、CORS、多 Key 与配额、缓存 TTL。
- 任何 API 字段、错误码、上限、队列容量、缓存键或淘汰策略的变更。

## 需求与验收标准

| 需求 ID | 需求 | 验收标准 |
| --- | --- | --- |
| REQ-025 | 请求日志包含队列等待、推理执行、入队时前方任务数与去重条数 | 成功、排队、排队超时三类请求的日志均含四个字段，值为非负整数，且不包含正文、向量或 Key |
| REQ-026 | 同一请求内重复文本只推理一次 | 输入 `["a","b","a"]` 时推理调用为 2 次，响应 3 条且顺序与 `index` 正确，`usage` 仍按 3 条统计；缓存开启与关闭行为一致 |
| REQ-027 | 过载响应给出退避提示 | `queue_full` 与 `queue_timeout` 的 429 均带 `Retry-After: 1`；其他错误不带该头 |
| REQ-028 | 不扩大运行面 | 不新增配置项、依赖或端点；现有 95 项非 real 测试继续通过；API 字段、错误码、上限、队列与缓存语义不变 |
| REQ-029 | 验证保持最小 | 单元测试覆盖三个需求；真实服务冒烟确认日志字段与响应头；未验证项明确记录，不扩大 ADR-0004 范围 |

## 约束与待讨论事项

- 日志只允许路径、状态码、耗时、批量、token、命中、队列与去重计数等安全元数据；不得记录正文、向量、Key 或底层异常。
- 不新增配置项，配置总数保持 18 项；不新增运行时依赖。
- 单 worker、请求级串行、20 个位置与 30 秒排队超时的语义不变；批内合批见 [PLAN-0011](../plans/0011-batch-inference.md)。
- 部署到 M4 与生产观察不在本 PRD 的授权范围内，需另行确认；本批先在当前仓库与本机验证。
- 待讨论：观察 1–2 周后再决定 O5（跨请求合并）与 O6（准入控制）的优先级；O9（GPU 合批）已由 [PLAN-0011](../plans/0011-batch-inference.md) 实施。
