- 状态：已确认，2026-10-21（范围与方向）；接口细节由 SPEC-0002 定义。
- 来源与确认依据：2026-10-21 用户明确要求新增本 PRD，确认这是产品范围变更，并选择“方案 A：BGE-M3 稀疏头”。本文件变更 [PRD-0001](0001-embedding-service.md) 中“首版仅提供稠密向量”的范围；PRD-0001 的其余需求继续有效。
- 关联：[PRD-0001](0001-embedding-service.md) · [ADR-0002](../adr/0002-bge-m3-mlx.md) · [ADR-0005](../adr/0005-native-sparse-head.md) · [SPEC-0001](../specs/0001-embedding-inference.md) · [SPEC-0002](../specs/0002-dense-sparse-output.md) · [PLAN-0007](../plans/0007-dense-sparse-output.md)

## 背景、用户与场景

现有服务只返回 1024 维稠密向量，已用于知识库 / RAG 的文档入库与在线查询。词面精确匹配（专有名词、编号、中文词）与语义召回各有盲区，调用方希望在同一套嵌入服务里同时获得 dense 和 sparse 两路信号，再自行做混合检索与融合排序。

BGE-M3 原生提供 sparse lexical weights，与 dense 共享同一次模型前向；当前 8bit 快照没有包含该 head，但官方模型提供独立的小型 head 文件，可以在不引入第二个模型、不增加语料统计服务的前提下补齐。技术可行性已完成核查；具体技术选择由后续 ADR 记录，接口与行为由 SPEC-0002 定义。

用户与调用方不变：内网知识库 / RAG 调用方，输入中英文混合纯文本，调用方负责文件解析、切分、存储、融合与检索；服务只负责嵌入计算。

## 目标与范围

目标：

- 一次请求、同一次模型前向同时得到 dense 与 sparse 两路结果，避免第二次推理或第二个稀疏模型。
- dense 的语义、维度、归一化和现有接口行为保持不变。
- sparse 采用 BGE-M3 原生稀疏头，不引入 BM25、SPLADE、语料统计或独立稀疏服务。
- 在 Mac mini M4 16GB 上保持现有长度与队列约束，8192 tokens 不因新增输出而不可用。

本次包含：

- 同一请求返回 dense + sparse；批量结果按输入顺序。
- sparse 的 token 级正权重映射；排除特殊 token；同一 token 多次出现取最大权重。
- 官方 sparse head 的获取、校验、加载与失败处理。
- 兼容性、错误、鉴权、队列、usage、日志与隐私规则的延续。
- M4 真实服务验证与相关文档更新。

本次不包含：

- ColBERT / multi-vector 输出。
- BM25、SPLADE、第二个稀疏模型或语料统计。
- 服务端混合排序、RRF、rerank、向量库或检索业务。
- 分词、词干化、同义词、IDF、长度归一化或检索效果调参。
- 修改模型主体、量化方式、训练或权重。
- 独立的新端点；两路在同一请求中返回。
- 生产级鉴权、多租户、管理页面。

## 成功标准

- 在 M4 真实服务上，一次请求返回 dense + sparse；中文、英文、混合文本的 sparse 非空、数值有限、权重为正；特殊 token 不出现。
- dense 输出与当前实现一致（同一输入下余弦 ≥ 0.9999；预期逐位一致）。
- 8192 tokens 请求成功且无 OOM；峰值内存和耗时与当前基线同量级，不出现数量级回退。
- 现有 dense-only 调用与测试通过；未启用 sparse 的响应不出现未约定的新字段。
- 不新增运行时依赖；sparse head 缺失时明确失败并给出安全错误，不静默降级或返回空结果。
- SPEC-0002、PLAN-0007、连接说明与 HANDOFF 已同步。

## 约束与待讨论事项

- 接口启用方式：同端点可选参数（推荐）或同一端点下的其他显式启用方式，由 SPEC-0002 决定；不新增独立端点，现有 dense-only 调用不得被迫改变。
- sparse key：token id 还是原始 SentencePiece token，由 SPEC-0002 决定；必须避免 decode 字符串造成的同键碰撞，并保证消费端可建立稀疏索引。
- 过滤与截断：默认保留全部正权重；是否提供 top-k 或阈值作为可选参数，由 SPEC-0002 决定，不得静默改变默认语义。
- 验证深度：按 [ADR-0004](../adr/0004-minimal-verification.md) 只做 M4 定向 smoke 与 8192 tokens 验证；与官方 fp16 全模型的数值对照需要 torch 与约 2.2GB 权重，暂不纳入。
- 质量声明：8bit encoder 加官方 fp16 head 不保证与官方 fp16 全模型逐位一致；本 PRD 不承诺检索效果提升，只承诺输出可用、语义可解释。
- 消费端：调用方需要支持稀疏向量的索引或存储；服务端不负责融合、排序或检索。
- ColBERT：本次不做；如后续需要，另立 PRD / ADR。
