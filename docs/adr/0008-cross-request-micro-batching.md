# ADR-0008：跨请求微合批

## 状态

已接受，2026-10-23。依据：用户在 [PLAN-0012](../plans/0012-inference-optimizations.md) 中确认跨请求微合批方向，并同意按 10–20ms 窗口、同 `return_sparse`、FIFO、单 worker 的默认边界继续。本记录只替代 [ADR-0007](0007-batch-inference.md) 中“不跨请求合批”的取舍；单 worker、单模型实例、单执行位、批内分组和外部 API 均不变。

## 上下文

当前执行链是“HTTP 请求 → 缓存/去重 → FIFO 队列 → 一个执行位 → `Embedder.embed`”。短请求（例如 1 条 25 token）的 GPU 利用率低，固定开销占比高；多个短请求同时到达时，逐个执行会重复支付每请求的 kernel 启动、逐层同步和 Python/MLX 调度成本。

已有批内合批只能摊薄同一请求内的条目，不能摊薄跨请求的固定开销。增加 worker 会引入 MLX 全局流冲突、内存翻倍和公平性问题，已被 [ADR-0007](0007-batch-inference.md) 排除。因此只考虑：在**不增加 worker/执行位**的前提下，把已经排队的短请求合并成一次前向。

约束：

- 外部 API、响应顺序、`usage`、缓存/去重、错误码、429/503 触发条件不变；
- 单请求顺序入库（尤其是 1M token 的分块入库）不应被额外窗口拖慢；
- 等待队列仍为 FIFO；不能因为合批让长请求无限饥饿；
- M4 16GB 上峰值内存不能接近 2 GiB 工作内存指导值；
- 失败需要尽量保持“一个请求失败不影响其他请求”的隔离。

## 决策

- **触发时机**：执行位完成当前作业后，如果等待队列中存在与下一个作业 `return_sparse` 相同的作业，最多等待 15ms（10–20ms 窗口的默认值）收集同批；窗口结束或达到上限即执行。若等待队列已经能填满本批上限，立即结束窗口，不再空等。若没有兼容等待者，立即执行，不为单请求增加固定延迟。
- **合并范围**：只合并 `return_sparse` 相同的等待作业；严格按入队顺序取作业。合计最多 16 个条目、8192 个原始 token（不含 padding）；下一个作业自身超过该预算时单独执行。超过上限的作业留在下一批，不插队。
- **执行**：把合并后的 token 列表交给现有 `Embedder.embed`，复用其按长度分桶、padding 和 sparse 切片；不能绕过现有推理预算。结果按每个作业的条目数切回各自的 future。
- **队列与延迟**：`queue_full`、`queue_timeout`、总位置数、`ahead` 的含义不变；被合批的等待作业在进入执行时取消排队计时。窗口等待计入该作业的 `wait_ms`，`exec_ms` 为合并前向的耗时。单请求顺序入库没有兼容等待者时不会触发窗口。
- **失败隔离**：合并前向失败时，按原 FIFO 顺序逐作业重试单请求推理；只有单作业也失败时才把该作业置为 `inference_failed`，不把合并失败直接扩散给同批其他请求。若重试导致重复 GPU 工作，只在异常路径发生。
- **不新增配置项**：15ms 窗口、16 条/8192 token 上限作为代码常量；若后续需要运维调参，再走配置/规格变更。
- **不做**：不改变 API 字段、缓存键、去重、鉴权、请求体限制、模型或 worker 数；不跨 `return_sparse` 合并；不对全命中请求排队。

## 替代方案

- **只在同一请求内合批**：实现最稳，但短请求并发的固定开销无法摊薄；本轮已由用户要求继续优化。未采用。
- **增加 worker**：可能提高并发，但会引入 MLX 默认流冲突、内存翻倍和公平性问题；与单 worker 约束冲突。未采用。
- **按 token 级持续合批/长窗口**：吞吐可能更高，但会显著增加尾延迟和调度复杂度，且不利于顺序入库。未采用。
- **合并失败直接整批返回**：实现更简单，但一个请求的异常会影响同批其他请求，破坏现有错误隔离。未采用。

## 后果

- 并发短请求可减少前向次数，预期改善吞吐和尾延迟；顺序入库的单请求路径基本不变，最多在“已有兼容等待者”时多等一个窗口。
- 需要新增调度器批处理状态、结果切分、逐作业失败重试和相应测试；调度复杂度上升。
- 15ms 是延迟/吞吐折中，不是容量承诺；真实收益取决于并发度、请求长度和缓存命中率。没有并发时不会产生收益。
- 失败重试可能使异常请求重复执行；正常路径不受影响。
- 需要真实并发测试验证 P95 不高于基线 + 窗口、结果正确、队列语义不变；证据记录在 PLAN-0012 及版本化数据文件中。
