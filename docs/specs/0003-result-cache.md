## 范围

`POST /v1/embeddings` 的进程内结果缓存：命中、部分命中与未命中行为，容量与淘汰，配置，日志与生命周期。不改变请求 / 响应字段、鉴权、错误码、长度与批量上限。

## 输入、输出与行为

### 查询时机与键

- 缓存查询发生在整个请求通过鉴权、解析与校验（含单条与总 token 上限检查）之后；无效输入永不进入缓存。
- 键为 `sha256(tokenizer 输出的 token id 序列二进制表示 ‖ 1 字节 return_sparse 标志)`，按文本条目粒度；不保存原文，不包含模型路径（缓存生命周期与模型实例绑定，进程重启即清空）。
- `return_sparse=true` 与 `false` 是不同键，互不串用。

### 命中与部分命中

- 请求内逐条查缓：命中的条目直接取结果，未命中条目组成子批进入调度任务；响应 `data` 仍按输入原顺序合并。
- 命中输出与同输入未命中推理输出逐位一致：dense 的 1024 项 JSON 数字相同；sparse 的条目顺序、token id 与数值相同。实现上命中转换使用与未命中相同的 `tolist()` 路径。
- `usage.prompt_tokens` / `usage.total_tokens` 仍为全部输入（含命中条目）token 数之和，语义不变。
- 全命中请求不创建调度任务、不占用执行位与等待位，不受 `queue_full` / `queue_timeout` 影响；仍受鉴权、请求体、批量与长度限制。`queue_full` / `queue_timeout` 仅可能发生在含未命中条目的请求。
- 命中刷新该条目的 LRU 最近使用时间。

### 回填与失败

- 回填发生在该条目推理成功并准备交付之后；推理失败（`inference_failed`）或客户端断开（响应被丢弃）不回填。
- 缓存不引入新错误码、新响应字段或新端点；缓存自身的读写不产生对外可见失败。

### 容量与淘汰

- 淘汰策略为 LRU；容量按估算字节累计：dense 每条 4096 字节，sparse 每条按 `32 × 项数` 估算；估算总量超过 `max_bytes` 时从最久未用条目开始淘汰，直至不超。
- 单条超过 `max_bytes` 的条目不缓存（避免不可淘汰项）；其余照常。
- 估算口径是内部保护值，不是进程 RSS 承诺；实际内存以实施阶段实测为准。

### 生命周期与隐私

- 缓存随应用 lifespan 创建，仅存在于进程内存；不落盘、不跨进程共享、不随日志输出；进程退出即消失。配置修改重启生效，即缓存整体重建。
- 键为单向哈希；缓存条目内容与响应内容相同（本就返回给调用方的向量），不新增落盘面。

## 约束

- 配置新增 `[cache]` 段：`enabled`（布尔）、`max_bytes`（正整数）。沿用现有严格校验：缺段、未知项、错误类型、非正数拒绝启动。配置项总数由 16 项增至 18 项；`config.example.toml` 同步更新，示例基线 `enabled = true`、`max_bytes = 268_435_456`（256 MiB，与 MLX 缓存回收目标同量级）。
- `enabled = false` 时不查、不填、不计命中数，行为与缓存引入前逐项一致。
- 不新增运行时依赖；缓存实现仅用标准库（`hashlib`、`collections.OrderedDict`）。
- 所有缓存读写仅在事件循环线程执行，不加锁；推理线程不接触缓存。
- 日志在现有请求完成日志（路径、状态码、耗时、批量大小 / token 数）基础上追加命中条数；不记录键、原文、向量或 sparse 权重。
- 验证按 [ADR-0004](../adr/0004-minimal-verification.md) 保持最小：定向单元测试 + 真实服务冒烟，不恢复复杂评测套件。

## 未决事项与关联计划

- `max_bytes` 实际生产值由私有 TOML 决定；256 MiB 为示例基线，实施时以本机 / M4 实测 RSS 校准。
- M4 部署、私有 `config.toml` 增段与线上验证需用户单独授权，见 [PLAN-0009](../plans/0009-result-cache.md)；部署注意：旧代码遇到未知 `[cache]` 段会拒绝启动，回滚须同步恢复配置文件。
- 命中率与生产收益依赖实际负载的重复度，本契约不预设命中率指标。
